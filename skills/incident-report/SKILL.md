# Incident report

Write a blameless incident report from what the user tells you (notes, chat logs, timestamps).

## Steps
1. Collect the facts: what broke, who and what was affected, when it started, was noticed and was fixed.
   If the start or end time is missing, ask once; otherwise write "unknown" — never invent times.
2. Separate the **cause** (why it happened) from the **trigger** (what set it off) and the **symptoms**.
3. List what was done to restore service, in order.
4. Propose follow-ups that stop it happening again; each one concrete and owned.

## Output
### Summary
Two or three sentences a manager can read.
### Impact
Who/what was affected, for how long, and how badly (users, services, data).
### Timeline
| Time | Event |
### Root cause
### Resolution
### Follow-up actions
| Action | Owner | Due |
### Lessons learned

Keep it factual and blameless: describe systems and decisions, not people's faults.
